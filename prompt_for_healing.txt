private Optional<LocatorCandidate> healViaLLM(
        WebDriver driver, By failedBy, HealContext ctx) {

    // 1. Compress DOM (caller passes pre-compressed JSON for token efficiency)
    String domJson      = domCompressor.compress(driver, failedBy);
    String similarJson  = domCompressor.findSimilar(driver, failedBy);

    // 2. Assemble prompt
    String userPrompt = promptAssembler.assembleUserPrompt(ctx, domJson, similarJson);

    // 3. Call LLM
    LLMGateway.LLMHealResponse llmResponse = llmGateway.callLLM(userPrompt);

    // 4. Parse + validate
    ParsedHealResult result = responseParser.parse(llmResponse, ctx);

    if (!result.isHealingPossible()) {
        log.warn("LLM healing blocked for {}: {}", ctx.getElementLabel(),
                 result.getBlockedReason());
        return Optional.empty();
    }

    // 5. Trial each candidate in rank order
    for (LocatorCandidate candidate : result.getValidCandidates()) {
        try {
            By by = toBy(candidate);
            driver.findElement(by);          // trial — throws if not found
            locatorVault.promote(ctx.getElementUuid(), candidate);
            log.info("LLM healed [{}] using strategy={} locator={}",
                     ctx.getElementLabel(), candidate.getStrategy(),
                     candidate.getLocator());
            return Optional.of(candidate);
        } catch (NoSuchElementException | StaleElementReferenceException e) {
            log.debug("Candidate rank {} failed trial: {}", candidate.getRank(),
                      candidate.getLocator());
        }
    }

    log.warn("All LLM candidates failed trial for {}", ctx.getElementLabel());
    return Optional.empty();
}

private By toBy(LocatorCandidate c) {
    return switch (c.getStrategy().toLowerCase()) {
        case "xpath"           -> By.xpath(c.getLocator());
        case "css", "cssselector" -> By.cssSelector(c.getLocator());
        case "id"              -> By.id(c.getLocator());
        case "name"            -> By.name(c.getLocator());
        case "linktext"        -> By.linkText(c.getLocator());
        case "partiallinktext" -> By.partialLinkText(c.getLocator());
        default                -> By.xpath(c.getLocator());
    };
}

The three decisions that make the biggest difference
The temperature: 0.0 setting is not a minor detail — it is the single most impactful API configuration change. At the default temperature of 0.7, the LLM generates different XPath syntax on every retry, making it impossible to detect true healing failures vs syntactic variation. At 0.0, output is fully deterministic: the same failed locator always produces the same candidates, which means your FAILED_HISTORY loop reliably prevents regenerating broken locators.
The response_format: json_object setting eliminates the most common production failure in basic LLM healing implementations — the LLM wrapping its JSON response in markdown code fences. Without this setting, JSON.parse() throws on every response and you end up with a brittle string-stripping workaround. With it, the API enforces valid JSON at the network level.
The intent_understood field in the output schema is not just metadata — it is a silent heal detector. When your ResponseParser reads "intent_understood": "cancel button to dismiss the form" for a heal request that targeted the save button, it knows the LLM identified the wrong element and can reject the candidates before any trial execution. No other tool in the market exposes this signal. It is what separates a 70% heal rate from a 90% one.
