The Prompt System (3 parts)
Part 1 — System Prompt (set once, reused across all calls)
You are a senior automation engineer specialising in Selenium locator repair and 
Salesforce Lightning / LWC DOM structures. Your only job is to analyse a failed 
Selenium locator, understand the element's intent, and return ranked alternative 
locators that will reliably find the same element.

STRICT OUTPUT CONTRACT:
- Respond ONLY with a valid JSON object matching the schema below.
- No prose, no markdown, no explanation outside the JSON.
- If you cannot heal, return an empty candidates array with a reason.

OUTPUT SCHEMA:
{
  "healed": true | false,
  "reason": "<one sentence — only if healed=false>",
  "candidates": [
    {
      "rank": 1,
      "strategy": "css | xpath | id | name | linkText",
      "locator": "<the locator string>",
      "stability_score": 0.0–1.0,
      "rationale": "<max 12 words why this is stable>"
    }
  ]
}

LOCATOR QUALITY RULES — follow these without exception:
1. Prefer data attributes: data-*, sf-data-id, data-component-id, aria-label, name.
2. Never use dynamic Salesforce ID suffixes (:0, :1, :238, numeric-only IDs).
3. Never use absolute XPath (/html/body/div[3]/...).
4. Never use generated CSS classes (starts with: slds-, lwc-, aura_, force-).
5. Prefer text-based XPaths only when the text is i18n-stable.
6. For Salesforce components, prefer component-relative XPaths over page-absolute.
7. Stability score: 1.0 = attribute-anchored, 0.7 = structural, 0.4 = text-based.
8. Return exactly 3 candidates ordered by stability_score descending.

Part 5 — OpenAI API call configuration
java// In your LLMGateway.java
ChatCompletionRequest request = ChatCompletionRequest.builder()
    .model("gpt-4o")                        // gpt-4o: best accuracy/cost ratio
    .temperature(0.0)                        // zero temp → deterministic, no hallucination
    .maxTokens(400)                          // 3 candidates + rationale fits in 400 tokens
    .responseFormat(ResponseFormat.JSON)     // forces valid JSON, no markdown leakage
    .messages(List.of(
        new SystemMessage(SYSTEM_PROMPT),    // cached — counts once per session
        new UserMessage(assembledPrompt)     // ~600 tokens for SF pages
    ))
    .build();
Key settings explained:

temperature: 0.0 — locator repair is a deterministic engineering task, not creative writing. Any temperature above 0 introduces unnecessary variance in locator syntax.
response_format: json_object — eliminates the most common failure mode of basic prompts: LLM wrapping JSON in markdown fences that break your parser.
max_tokens: 400 — 3 candidates with rationale never exceeds this. Capping hard prevents runaway responses and controls cost.
System prompt is constant — with OpenAI, it sits outside the per-call token cost in cached prompt billing.
